# 엑셀 임시 테이블과 AI 쿼리 작성

## 범위와 사용법

이 기능은 **범용 엑셀 작업**이다. 정산·고객 매칭·기간 분할 등 특정 업무 규칙을 내장하지 않는다. 어떤 열을 어떻게 비교·조회·수정할지는 사용자가 AI에 지시한다.

1. 사용할 DB 연결을 선택하고 연결한다. 엑셀 임시 데이터는 읽기 전용 연결에서도 사용할 수 있다.
2. 왼쪽 **엑셀 가져오기**에서 `.xlsx` 파일과 시트를 선택하고 로컬 임시 적재한다. 첫 행은 열 이름이며 샘플은 최대20행이다.
3. **선택한 연결에 임시 테이블 등록** 후 표시되는 `[import].[stage_<무작위값>]` 이름을 사용한다. 같은 연결의 일반 테이블과 JOIN할 수 있다.
4. **AI에 이 테이블 활용 요청**을 누르고 CLI 상태를 확인한 뒤 원하는 작업을 입력해 전송한다. 선택 DB와 엑셀 임시 테이블의 구조는 자동 공유되며 체크박스는 없다. 요청 준비만으로 AI를 호출하지 않는다. 예: “엑셀 상품코드와 상품 테이블을 연결해서 없는 코드만 찾는 SELECT를 작성해줘.”
5. AI가 생성한 SQL 제안을 새 SQL 탭으로 연다. 지원되는 SELECT는 기존 실행 경로로 조회한다. UPDATE/INSERT/MERGE/복잡한 SQL은 `draft=true`인 **미검증·실행하지 않은 초안**으로 생성할 수 있다. 초안 생성이 업무 데이터 변경이나 범용 SQL 실행 지원을 뜻하지 않는다.
6. 아래 형식에 맞는 초안은 개발용 쓰기 연결에서 **UPDATE/DELETE 미리보기 → 트랜잭션에 적용 → DB 이름 확인 COMMIT**으로 실행할 수 있다(ADR-018).

## 엑셀 JOIN 쓰기 (개발 연결 전용)

```sql
-- 기존 행 수정: 엑셀 행과 일치하는 대상만 바뀐다
UPDATE t SET amount = TRY_CONVERT(decimal(18, 2), s.[금액])
FROM dbo.정산 AS t
JOIN [import].[stage_...] AS s ON t.[기관코드] = s.[기관코드]

-- 없는 행 추가: 같은 테이블 LEFT JOIN + IS NULL로 기존 행 제외
INSERT INTO dbo.정산 ([기관코드], amount)
SELECT s.[기관코드], TRY_CONVERT(decimal(18, 2), s.[금액])
FROM [import].[stage_...] AS s
LEFT JOIN dbo.정산 AS t ON t.[기관코드] = s.[기관코드]
WHERE t.[기관코드] IS NULL
```

- 값은 리터럴, 엑셀 열, `TRY_CONVERT(형식, 엑셀 열)`만 허용한다. 계산식/함수/대상 열 참조는 거부한다. 엑셀 원문 텍스트는 nvarchar/nchar 열에만 넣을 수 있다(빈 값이 0·1900-01-01로 바뀌는 암묵 변환과 varchar의 유니코드 `?` 손실 방지). varchar 열에는 아직 원문을 넣을 수 없다.
- ON은 `대상 열 = 엑셀 값` 비교를 AND로만 연결한다. WHERE는 열과 리터럴 비교만 지원한다. INSERT의 LEFT JOIN 대상은 INSERT 대상과 같은 테이블이어야 한다.
- 미리보기는 대상 1~1000행을 요구한다. 변환 실패나 빈 값이 하나라도 있으면 행 수와 함께 거부하므로 WHERE로 제외하거나 원본을 고친다. ON의 엑셀 키가 비었거나 변환에 실패해도 거부한다(INSERT 중복 방지). WHERE 안의 변환 실패는 제외 행이 될 뿐이다. 미리보기는 엑셀 전체 행 수와 함께 UPDATE는 ON 조건으로 대상과 일치하지 않는 엑셀 행 수, INSERT는 추가하지 않는 행 수(기존 행과 일치·WHERE 제외)를 보여준다(ADR-027). 미일치 수는 WHERE를 적용하지 않은 ON 기준이며 잠금 재확인에서는 다시 계산하지 않는다.
- UPDATE는 대상 행 하나가 엑셀 행 여러 개와 일치하면 거부한다. 기존 rowversion 집합 검증을 그대로 쓴다. INSERT는 rowversion이 없으므로 삽입할 행 전체의 digest를 미리보기와 잠금 재조회에서 비교하고, 그 사이 다른 세션이 행을 넣어 결과가 바뀌면 rollback한다.
- 미리보기는 같은 세션에 `#stage_...`를 만든 rollback 전용 트랜잭션에서 읽는다. 적용은 SERIALIZABLE 쓰기 트랜잭션에 다시 적재한 뒤 실행한다. 대상 테이블 조건(PK·NOT NULL rowversion·트리거/CHECK 없음 등)과 INSERT 권한은 기존 쓰기 정책과 같다.
- 한 번의 COMMIT은 SQL 문장 하나다. "기존 기간 종료 + 새 기간 추가"처럼 두 문장이 필요한 작업은 각각 미리보기·COMMIT하며, 두 문장을 하나의 원자적 작업으로 묶지는 않는다.

## 실제 테이블과 데이터 경계

- 업로드 원본은 Main의 메모리 전용 SQLite TEMP 테이블에 보관한다. 설정 SQLite/디스크/AI에 셀 값을 자동 저장·전송하지 않는다. 원본 파일은 수정하지 않는다.
- `[import].[stage_...]`는 앱이 소유한 논리적 참조다. 업로드·등록 때 SQL Server의 영구 테이블을 만들거나 업무 데이터를 바꾸지 않는다.
- SELECT 실행 때만 드라이버의 한 물리 연결을 짧은 트랜잭션으로 고정한다. 고정 DDL의 `Request.batch()`로 실제 로컬 `#stage_...`를 만들고, 단일 파라미터 JSON으로 데이터를 적재해 쿼리를 실행한 뒤 rollback으로 정리한다. `##` 전역 임시 테이블이나 사용자 DB 영구 staging 테이블은 사용하지 않는다. SQL Server 호환성 수준130 이상(OPENJSON)이 필요하다.
- 테이블 참조 치환은 파서의 FROM/JOIN 렌더링에서만 수행한다. SQL 문자열/셀 값의 텍스트 치환이나 임의 실행 브리지를 추가하지 않는다.
- 연결별 소유 목록·세대와 등록 변경 revision을 검사한다. 삭제/등록 변경은 기존 승인과 AI 메타데이터 scope를 무효화한다. 실행 중인 조회/메타데이터와 등록·삭제는 섞이지 않는다.
- `import` 스키마의 `stage_`+32자리 소문자16진수 이름만 예약한다. 다른 실제 `import` 스키마 테이블은 기존 DB 경로로 접근한다. 논리 이름을 그대로 외부 SSMS에 복사하면 실행되는 영구 테이블이 아니다.
- 등록은 연결 종료/명시적 삭제/앱 종료로 해제된다. 로컬 원본은 별도 삭제하거나 앱을 종료할 때 제거한다. 미등록 원본은 다음 가져오기 작업의30분 만료 검사 대상이며, 등록된 원본은 명시적으로 삭제할 때까지 보호한다. 다중 연결 삭제 중 일부 연결이 바쁘면 완료된 해제는 유지하고 남은 작업은 재시도할 수 있다.

## 데이터 보존과 제한

- 모든 SQL 임시 컬럼은 `nvarchar(max)` 텍스트다. 선행0/사업자번호/원래 소수 문자열을 유지하며 임의 숫자형 추론을 하지 않는다. 빈 셀은 XLSX 파서에서 빈 문자열이 될 수 있다.
- 숫자·날짜 조건/집계에는 제한된 `TRY_CONVERT(int|bigint|decimal(p,s)|numeric(p,s)|date, 식 [,23|112|126])`를 쓸 수 있다. 실패 값은 SQL Server에서 NULL이 되므로 변환 실패 검사를 먼저 작성하도록 요청한다. p는1~38, s는0~p다. 일반 CAST/CONVERT·CTE·임의 T-SQL 실행은 지원 범위 밖이다.
- 원본 소수 문자열의 정확한 보존과 숫자형 조회 결과의 표시 정확도는 다르다. 기존 MSSQL 드라이버의 숫자 결과는 JavaScript Number이므로 큰 DECIMAL의 정밀도를 보장하지 않는다. 중요한 원본 수치 검증은 텍스트 값을 함께 확인한다.
- `.xlsx`(ADR-036, Node 파서·OS 무관): 파일32MiB/ZIP4096항목·압축해제256MiB/출력64MiB/최대32시트·시트50,000행·256열·셀8192문자. 열린 파일3개/로컬stage8개/연결별등록8개·전체64MiB다. 파일을 연 뒤 시트를 골라 적재한다.
- 값만 읽는다: 수식은 저장된 결과값, 하이퍼링크·병합·외부 연결·이진 파트는 무시, 지수·긴 숫자·알 수 없는 서식·오류 셀(#N/A)은 저장된 텍스트, 시각 있는 날짜는 `yyyy-MM-dd HH:mm:ss`. 첫 비어 있지 않은 행이 헤더이며 빈/중복/긴 이름은 `열N`·`_2`·120자로 바꾸고, 헤더도 데이터도 없는 열은 버린다. 매크로(vbaProject)·암호화·DTD·ZIP 경로 조작은 거부한다. 구형 `.xls`는 미지원이다.
- AI 메시지 전송 시 선택 DB와 등록된 임시 테이블의 메타데이터를 자동 공유한다(ADR-023). 열 이름도 외부 AI에 공유되는 정보다. 행·샘플·DB 암호는 도구 응답에 포함하지 않는다. AI에 직접 입력한 메시지는 공식 CLI 기록에 남을 수 있다.

## 검증

단위 회귀: import-workbook(실제 XLSX 파서), import-service(대역), import-sql(등록/파서/변환), database-service(세대·scope·경쟁), mcp(메타데이터·미검증 초안).

Electron: import-workspace는 명시적 핸들러 대역의 UI 흐름이다. import-file은 OS 파일 선택기만 대역으로 사용하며 실제 Main 파서/SQLite를 사용한다. 실제 DB 가지는 별도 opt-in으로 같은 XLSX가 SQL Server #temp SELECT까지 이어지는지 확인한다.

실제 DB: `tests/integration/imports.test.ts`는 WRITE_TESTING.md의 전용 fixture 환경에서 실행한다. 미리 만들어 둔 전용 DB와 분리된 준비용/조회용 자격 증명이 필요하며 암호를 파일에 기록하지 않는다. 테스트는 자기 소유 fixture만 만들고 제거한다. 사용자 업무 파일/업무 스키마·운영 성능·Production TLS 수용을 대신하지 않는다.

실제 AI 회귀는 `tests/e2e/live-import-ai.spec.ts`에 있으며 전용 fixture/조회 계정과 `AI_DB_TEST_IMPORT_AGENT=1`을 함께 설정해야 한다. 이 검사는 합성 XLSX의 무작위 테이블·열을 실제 Codex가 MCP로 발견하고 SELECT 제안/별도 변경 초안을 만드는지 확인한다. 자동으로 활성화하거나 사용자 업무 행 값을 AI에 보내지 않는다.

## 2026-10-29 실제 AI 재검증 완료

기존 Codex 사용량 한도 때문에 미완료였던 `live-import-ai.spec.ts`가 실제 Codex0.165.0/ChatGPT 구독·로컬 SQL Server에서 통과했다. 모델에 알려주지 않은 무작위 업로드 테이블·열을 MCP로 발견해 SELECT를 제안하고 실제 결과를 조회했다. 행 값이 AI 이벤트에 공유되지 않으며, 이어서 만든 UPDATE/JOIN draft는 SQL 탭에만 열리고 업무 행/이력은 그대로인 점을 확인했다. 실제 JOIN 변경 실행은 별도 `import-mutations.test.ts`의 승인·commit/rollback 검증도 이번에 통과했다. 사용자 업무 파일/운영 환경 수용과는 구분한다. 전체 검증 수와 증거 로그는 PROGRESS의2026-10-29 항목을 따른다.
