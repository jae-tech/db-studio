# 가상 관계 (가상 FK)

실제 FK가 없어도 **테이블 연결 기준과 업무명**을 앱에 등록하고 AI의 JOIN 작성에 활용할 수 있다. SQL Server의 FK/테이블/행을 생성하거나 변경하지 않는다.

## 사용

테이블 상세 화면(탐색기에서 테이블 클릭) 아래에서도 같은 편집기를 쓸 수 있다. 클릭한 테이블이 기준 테이블로 고정되고, 연결 테이블을 고르면 같은 이름 열(연결 테이블 PK 우선)이 자동으로 채워지며 업무명을 비우면 연결 테이블 이름으로 저장한다(ADR-029).

1. SQL 탭에서 연결/DB를 선택하고 연결한다.
2. 왼쪽 **가상 관계** 아이콘을 연다.
3. 업무명(`부가서비스 밴`), 별칭(`VAN`), 기준/연결 테이블과 양쪽 열을 선택한다.
4. LEFT/INNER JOIN과 관계 유형을 지정한다. 복합키는 **연결 열 추가**로 최대 8쌍을 등록한다.
5. **관계 검증 후 저장**을 누른다. 실제 테이블·열이 존재하는지 다시 확인한다.
6. AI에 `부가서비스 밴 조회해줘`처럼 질문한다. AI는 등록된 업무명/별칭·열·JOIN 기준을 참고해 SQL을 제안한다. 제안 열기 후 SELECT를 실행한다. 기존 쓰기 승인 정책은 바뀌지 않는다.

세 개 이상 테이블은 A→B, B→C 관계를 이어서 등록한다. 같은 업무명을 관련 관계에 사용할 수 있다. 관계 카드를 눌러 수정하거나 삭제한다. 삭제도 앱 설정만 바꾼다.

## 저장·격리

- 기존 SQLite `preferences.db`의 엄격한 settings DTO에 저장한다. 구버전 설정에는 빈 목록을 기본값으로 적용한다.
- 연결 ID + DB 이름별로 분리한다. 다른 연결/DB에 자동 적용하지 않는다. 같은 프로필을 다른 서버로 편집/재사용할 때는 관계를 직접 재확인해야 한다.
- DB별 최대 20개, 전체 100개, 별칭 8개, 복합 연결 열 8쌍이다. 임의 ON 식/SQL 조각은 받지 않으며 열 간 동등 연결만 표현한다.
- 관계명/별칭/설명도 연결된 AI 대화에서 공유되는 메타데이터다. 비밀값·실제 행 데이터를 입력하지 않는다. 저장 자체로 AI를 호출하지 않는다.
- Main이 현재 settings에서 읽는다. Renderer가 Agent 요청에 관계나 권한을 직접 넣지 않는다. 기존 고정 IPC만 재사용한다.

## AI·검증 경계

`db_list_tables`가 업무명/별칭과 관계 힌트를 반환한다. `db_get_foreign_keys`는 실제 `foreignKeys`와 **별도** `virtualRelationships`를 반환하며, 양쪽 테이블/열 존재 여부를 확인한다. 들어오는 관계와 나가는 관계 모두 발견할 수 있다. 존재 확인에는 기존 세대별 최대 30초 메타데이터 캐시가 적용된다. `columns-present`는 유일성/자료형 호환/실제 행 일치를 보장한다는 뜻이 아니다. 테이블/열이 없거나 접근할 수 없으면 `invalid`로 표시하고 사용하지 않도록 안내한다.

관계 수정/삭제는 범위 해시와 재개 키를 바꾼다. 이전 턴의 도구·제안은 더 이상 유효하지 않으며 다음 질문은 새 범위로 시작한다. DB 단절/세대 변경 보호도 그대로다. 이미 편집기에 열린 SQL은 자동 변경하지 않으며 실행 시 기존 Main 정책을 다시 통과해야 한다.

관계 메타데이터는 명령이 아닌 신뢰하지 않는 데이터로 취급한다. 업무명이 중복·모호하거나 필요한 필터 값이 없으면 AI가 확인하도록 지시한다. 업무명만 보고 `서비스유형='VAN'` 같은 실제 코드 값을 만들어 내지 않도록 한다. AI의 의미 해석이나 임의 SQL 정확성을 결정적으로 보장하는 기능은 아니다.

관계 유형은 사용자 힌트이며 DB 제약을 대신하지 않는다. 일대다/다대다 JOIN은 결과를 증식시키고 집계를 중복할 수 있다. 자동 DISTINCT/집계로 숨기지 않고 생성 SQL을 확인한다. 임의 조건·고정 값 필터·교차 DB 관계·다형성 관계·데이터 품질 검사·ER 다이어그램/자동 관계 추론은 이번 범위가 아니다.

기존 MCP 호출/출력/시간 예산을 유지한다. 한 응답의 관계 목록은 UTF-8 12KB 내로 자르고 `virtualRelationshipsTruncated`로 알린다. 잘린 목록을 완전한 관계 목록으로 가정하지 않는다. 스키마 필터로 범위를 줄일 수 있다. 행·엑셀 셀·자격 증명이나 새로운 DB 실행 도구는 공유/추가하지 않는다.

## 검증

- `tests/unit/relationships.test.ts`: 설정 기본값/상한/복합키/범위 해시·격리/수정·단절 후 거부/실제 FK와 구분/열 누락/예산.
- `tests/e2e/relationships.spec.ts`: 실제 Electron/SQLite + 메타데이터 핸들러 대역. 생성·편집·복합키·저장 후 재읽기·DB 분리·삭제·없는 열 거부·실행 이력 없음.
- `tests/e2e/live-relationships.spec.ts`: opt-in 전용 SQL Server의 FK 없는 테이블 두 개, 실제 UI 관계 저장, 공식 Codex의 업무명 발견·메타데이터 확인·LEFT JOIN 제안, SELECT-only 계정 결과 조회. 실행 전 이력 없음/행 비공유/실제 FK 여전히 0개를 확인한다. 실행 기록은 PROGRESS 기준이다.
